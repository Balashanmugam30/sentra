## 1. Overview & Service Architecture

- **Frontend / Edge Layer (Vercel):** Next.js 16 App Router application hosted at `https://sentra-01.vercel.app`.
- **Backend / Intelligence Layer (Render):** FastAPI (Python 3.12) high-performance API service orchestrating the multi-modal crisis data plane, deterministic forecasting engine, MLOps model registry, and Google Gemini multimodal crisis intelligence.

## 2. Infrastructure as Code: `render.yaml` Blueprint

The backend service is declaratively provisioned via the root `render.yaml` Infrastructure as Code blueprint:

```yaml
services:
  - type: web
    name: sentra
    runtime: python
    region: oregon
    plan: free
    branch: main
    buildCommand: "pip install -r requirements-prod.txt"
    startCommand: "uvicorn app.main:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips '*'"
    healthCheckPath: /health
    autoDeploy: true
    envVars:
      - key: PYTHON_VERSION
        value: "3.12.0"
      - key: APP_ENV
        value: "production"
      - key: SENTRA_COOKIE_SECURE
        value: "true"
      - key: JWT_SECRET
        generateValue: true
      - key: SECRET_KEY
        generateValue: true
      - key: ALLOWED_ORIGINS
        value: "https://sentra-01.vercel.app,http://localhost:3000,http://127.0.0.1:3000"
      - key: SENTRA_ENABLE_DEMO_SEED
        value: "true"
```

### Key Blueprint Guarantees:
1. **Dynamic Port Binding:** Uvicorn binds to `$PORT` supplied dynamically by Render's container runtime, avoiding rigid port crashes.
2. **Reverse Proxy Header Support:** `--proxy-headers --forwarded-allow-ips '*'` ensures client IP addresses and TLS termination protocols (`X-Forwarded-Proto`) are respected for HTTPS cookie flags.
3. **Automated Cryptographic Secrets:** `JWT_SECRET` and `SECRET_KEY` are cryptographically auto-generated by Render's secret engine during initial provision.
4. **Zero-Downtime Continuous Deployment:** `autoDeploy: true` automatically triggers builds and rolling container redeployments upon every commit to `origin/main`.

## 3. Environment Variable Contracts

| Variable Name | Required | Default / Example | Purpose / Contract |
| :--- | :---: | :--- | :--- |
| `PYTHON_VERSION` | Yes | `3.12.8` | Enforces exact Python runtime consistency (also mirrored in `.python-version`). |
| `APP_ENV` | Yes | `production` | Switches log verbosity and cookie security policies. |
| `ALLOWED_ORIGINS` | Yes | `https://sentra-01.vercel.app,...` | Strict CORS origin whitelist for Cross-Origin requests. |
| `JWT_SECRET` | Yes | Auto-generated | Signs and verifies user session JWTs (required $\ge 32$ chars in production). |
| `SECRET_KEY` | Yes | Auto-generated | Session cookie encryption secret. |

| `SENTRA_ENABLE_DEMO_SEED` | No | `true` | Seeds initial incident scenarios and active sensor streams for testing. |

## 4. Production Startup Safety Gating & Diagnostic Codes

Sentra implements strict production environment gating in `app/core/startup_checks.py`.

### Startup Checks & Blocking Codes:
- **`SEC_JWT_SECRET_BLOCKED`:**
  - **Condition:** In production (`APP_ENV=production`), `JWT_SECRET` (or `SECRET_KEY`, `SENTRA_JWT_SECRET`) must be provided via environment variables with $\ge 32$ characters of entropy, OR generated and persisted via the hosted instance secure key store (`data/.sentra_secret_key` on single-instance / Render deployments with `RENDER=true` or `SENTRA_PERSIST_SECRET=true`).
  - **Behavior:** The application refuses to boot with an unmanaged ephemeral in-memory secret in production, preventing unexpected session loss across multi-instance restarts while allowing zero-configuration boot on Render.
  - **Safe Diagnostics:** Emits structured log event `startup_check_blocked` with `check_name`, `error_code`, `status=blocked`, and reason without leaking secret values.
- **`SEC_RUNTIME_MODE_BLOCKED`:**
  - **Condition:** Valid runtime mode (`production`, `staging`, `enterprise`, `development`).

## 5. Render MCP Integration & Authentication Policy

To allow AI agents (including Antigravity) to monitor, inspect logs, and manage Render deployments via MCP without getting blocked by dynamic OAuth registration issues:

### Wrapper Location:
`tools/render-mcp-wrapper.js`

### Authentication Architecture:
- The hosted Render MCP endpoint is `https://mcp.render.com/mcp`.
- Render's MCP endpoint requires static Bearer token authentication: `Authorization: Bearer <RENDER_API_KEY>`.
- When `RENDER_API_KEY` is not present in the environment, the wrapper reports a clean actionable error message rather than attempting an unsupported OAuth dynamic client registration.

## 5. Deployment Verification & Health Check Endpoints

Once deployed on Render, the backend service exposes the following verification endpoints:

1. **System Health:**
   - `GET /health`
   - Returns: `{"status": "ok", "environment": "production", "version": "1.0.0"}`

2. **Data Plane Sensor Telemetry:**
   - `GET /data/streams/summary`
   - Returns aggregated sensor health, total envelopes, and average quality scores.

3. **Calibrated Prediction Engine:**
   - `GET /predictions/incident/{incident_id}`
   - Returns 5-horizon forecasts with calibrated 90% uncertainty intervals `[lower_bound_90, upper_bound_90]`.

4. **MLOps Governance & Drift:**
   - `GET /mlops/registry/status`
   - Returns active production model, shadow candidate model, divergence flags, and PSI drift scores.

## 6. Operational Resilience & Fallback

In the event that the Render backend is cold-starting or temporarily unreachable, the frontend at `https://sentra-01.vercel.app` implements:
1. **Resilient Local Synthetic Fallbacks:** `lib/data/prediction-service.ts` provides calibrated deterministic fallbacks for continuous zero-downtime operation.
2. **Transparent UI Status Badges:** The Prediction Cockpit UI surfaces `STREAM HEALTH`, `CALIBRATED_FALLBACK`, or `HIGH_CONFIDENCE_INFERENCE` so operators always know the operational state of the intelligence plane.
